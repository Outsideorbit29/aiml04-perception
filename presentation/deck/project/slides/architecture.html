  • The bridge ticks CARLA only after control for the last frame arrives, so slow perception never desyncs the sim
  • A lead must stay in the ego lane for 3 frames under one track id before the controller reacts
Time: 1:00. CARLA runs on Windows. ROS2 Humble runs in WSL2 with four nodes. The bridge is the only node that talks to CARLA: it publishes the camera image and odometry and applies the control. The perception node wraps one Python pipeline that has no ROS code in it: YOLO detection, ByteTrack, YOLOP lanes, MiDaS depth every second frame, and distance fusion with a per-track Kalman filter that gives closing speed and time to collision. The control node picks the mode: autopilot, adaptive cruise, gap keeping, emergency braking, or hold. A fourth node records the video. CARLA runs in synchronous mode, so slow perception never desyncs the simulation; the cost is that the loop runs slower than real time. On the cloud side, Kaggle jobs clone the repo at a commit and push metrics, weights and ONNX files to W&B.
