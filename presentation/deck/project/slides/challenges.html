Time: 0:55. First, the runtime: ONNX Runtime’s GPU provider would not load in WSL2, so the first live run had the detector on the CPU at 130 ms; I went straight to TensorRT engines built on the laptop. Second, Kaggle: reading the mounted dataset ran at 0.6 to 0.7 MB/s, so jobs copy data to local disk first, and a MiDaS torch.hub dependency waited for a trust prompt a batch job can’t answer. [Fill in: Kaggle queue waits you hit.] Third, assumptions the data broke: MiDaS helped on KITTI but made CARLA distances worse (0.040 to 0.087 on ground-truth boxes), and the box-bottom calibration was only right for the detector it was fitted on. Fourth, control: the first runs switched between slow-down modes and ended in emergency braking; hysteresis, a minimum dwell, a rate-limited brake and a 10 m minimum gap fixed that. Last, the laptop itself: with 16 GB of RAM, CARLA stopped answering when memory ran out, so each scenario now gets a fresh CARLA and WSL is shut down between runs.
